# «Приміряти фасад» — MVP

Проёмы дополнительно ищет локальный Grounding DINO Tiny (~689 МБ весов).
Перед первым запуском выполните `python tools/prepare_facade_models.py`, задав
тот же `HF_HOME`, который использует сервер (для локальной разработки —
`.facade-data/model-cache`). Скрипт скачивает только модели, фото не передаются.
Версия детектора закреплена в `openingDetectorRevision`. Во время заявки его
веса не скачиваются. Если кэша нет или детектор дал сбой, примерка продолжает
работать с предупреждением о необходимости выделить проёмы вручную.
Пустое `openingDetectorModel` отключает дополнительный детектор.
Он добавляет нагрузку на CPU и память; прежний ориентир RAM ниже требует
повторного измерения с двумя моделями. Детектор не гарантирует полноту проёмов.

Добавлен ручной редактор окон, дверей, цоколя и контура фасада. Использование,
хранение исправлений и отдельное согласие на обучение описаны в [EDITOR.md](EDITOR.md).

Автоматическая примерка доступна на `/lab`: 46 панелей керамогранита, польского клинкера и имитации. Главная страница использует отдельную форму заявки менеджеру; она не запускает модель. Ссылки `/result/{UUID}` открывают автоматическую примерку с редактором. Фото и контактные данные отправляются только после согласия и нажатия кнопки формы. До трёх фактур обрабатываются на одной маске фото клиента. Заявки лаборатории и почтовые заявки каталога учитываются отдельно.

## Запуск

Перед первым запуском подготовьте фактуры: `python tools/prepare_facade_textures.py`.
Команда проверяет встроенные изображения и скачивает недостающие фактуры каталога
в `.facade-data/texture-cache` (или в `FACADE_DATA_DIR/texture-cache`). Повторный запуск
проверяет и переиспользует готовые файлы. `python tools/prepare_facade_textures.py --check`
проверяет все фактуры без обращения к сети и возвращает ненулевой код при проблеме.
Кэш привязан к полному URL; при смене URL нужна повторная подготовка. Если содержимое
по прежнему URL изменилось, соответствующий файл кэша нужно обновить отдельно.
Во время примерки сайт фактур не запрашивается. Отсутствующая или повреждённая
заранее скачиваемая фактура отклоняет новую заявку до постановки в очередь.
Кэш не входит в Git: при переносе на другую машину подготовку нужно повторить.

Это серверный модуль. GitHub Pages и открытие index.html не запускают сегментацию или запись заявок. Нужен Python-сервер с 4 ГБ RAM или больше, постоянным диском и HTTPS. Ориентир CPU/RAM нужно проверить нагрузочным тестом на выбранном хостинге.

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux: source .venv/bin/activate
pip install -r facade/requirements.txt tzdata
python tools/export_facade_catalog.py
python -m uvicorn facade.app:app --host 127.0.0.1 --port 8000 --no-access-log
```

Открыть http://127.0.0.1:8000. При первом старте модель SegFormer скачивается с Hugging Face, затем используется локально. Фото в сторонние AI-сервисы не отправляются. До загрузки модели health.ready=false, обработка закрыта. Ошибка загрузки модели требует перезапуска после устранения причины. Для Docker: `docker build -f facade/Dockerfile -t nashdvor-facade .`, затем `docker run -p 8000:8000 -v facade-data:/data --env-file .env nashdvor-facade`. `.env` создаётся вне Git.

Один процесс uvicorn (без --workers): один экземпляр модели, последовательная очередь до трёх заданий. Перед публичным запуском ограничить reverse proxy: тело запроса 11 МБ, таймаут загрузки, частоту обращений. IP для ограничений берётся из request.client; доверять proxy headers только от настроенного прокси. Хранилище и резервные копии должны быть закрыты на уровне хостинга. Не публиковать `.facade-data`, базу или кэш модели. TLS и шифрование постоянного диска настраиваются на сервере.

После интеграции P0 от 30.10.2026 POST/PUT/PATCH требуют Content-Length; запросы с Transfer-Encoding отклоняются с 411 до разбора multipart. Обычная форма Chromium проверена с PNG и HEIC; поведение мобильного браузера и внешнего reverse proxy отдельно не проверялось. Неверный Content-Length даёт 400, превышение заявленного лимита — 413. Перед публичным размещением по-прежнему нужны ограничения фактического входящего потока/таймаутов на прокси; проверка заголовка не заменяет все меры ограничения ресурсов.

Таймаут осиротевших queued/processing — stuckJobSeconds=1800, проверяется при новом принятом по качеству фото. Задания, которые реально выполняются или ожидают модель внутри текущего процесса, исключены из этой проверки; остановить зависший поток этот механизм не может. Начальная загрузка записи и её валидация теперь внутри обработчика ошибок. Соединения SQLite закрываются после завершения транзакции. Режим остаётся строго однопроцессным.

## Данные и текстуры

`catalog-data.json` экспортируется из исходного CATALOG, без изменения цен. После любых изменений товаров запускать `python tools/export_facade_catalog.py` и тест синхронизации. Новые поля: visualizationTexture, tileSize, colors, tier. Неизвестные tileSize/tier — null. Существующие исходники используются как приблизительные повторяемые фактуры. Каталожные снимки не объявляются профессионально подготовленными бесшовными текстурами. Для замены указать visualizationTexture в CATALOG: встроенное data:image, HTTPS на nashdvor.com.ua или `textures/file.png` внутри проекта. Сторонние хосты и перенаправления запрещены.

SegFormer ADE20K сначала использует явный класс wall. Если фасад распознан как building/house, запускается дополнительное выделение поверхности через GrabCut внутри крупнейшего семантического компонента. Внутренние образцы цвета включают солнечную и теневую части стены; крыша отделяется по внешнему виду. Семантические исключения окон, дверей, неба и других объектов не заполняются. Здание целиком напрямую не закрашивается: если дополнительное выделение не даёт полезного разделения, результат отклоняется. Для такого способа confidence ограничен 0.74 и выводится предупреждение. Это эвристика: одинаковый цвет крыши и стены может затруднить разделение; качество на разнообразных фасадах ещё нужно измерить.

Маска сохраняет полную форму стены, включая треугольный фронтон. Если контур не помещается в четырёхугольник, ограничивающий прямоугольник задаёт только координаты текстуры; границы покраски определяет маска. Эрозия защищает границы исключений, мелкие и неоднозначные поверхности отклоняются. Обработанный PNG сохраняет пиксели вне маски без изменений. EXIF/GPS удаляется при декодировании. Проверены два пользовательских примера с оштукатуренной стеной и утеплителем: оба проходят без снижения порогов резкости и confidence. Эти фото и диагностические результаты хранятся только локально, в репозиторий не включены.

Confidence — инженерная эвристика, а не калиброванная вероятность. Факторы: вероятность класса wall, доля стены, согласованность контура с четырьмя углами, доля исключений и перспектива. Пороги 0.5/0.75, резкость, экспозиция, время хранения и шаблонная раскладка — в `facade/config.json`. Стены с несколькими крупными компонентами отклоняются; это намеренно увеличивает число пересъёмок. Нужны 50–100 размеченных фото перед рекламным запуском. TileSize влияет только на отношение сторон условной раскладки; реальный масштаб без измерений не определяется. Условный масштаб определён так: `templateRepeats` колонок плитки укладывается по ширине плоскости стены, а холст раскладки имеет те же пропорции, что и плоскость (`plane_aspect` в core.py: полусуммы противоположных сторон четырёхугольника). Поэтому плитка не растягивается по форме стены. Это экранная пропорция, а не физический размер: на сильно косом снимке она остаётся приближением, а на широкой стене панели выглядят относительно крупнее, чем на узкой.

Керамогранит имеет цену за панель 0,564 м². Расчёт: ceil(площадь / 0,564) × цена панели, с явным количеством. Клинкер/имитация: площадь × исходная цена за м². Денежные вычисления — Decimal. Запас на подрезку не включён. Неизвестная площадь, основа/толщина и отсутствующая цена не заменяются нулём. Расчёт датируется в Europe/Kyiv, действует 14 дней.

Ограничение итерации пропорций: plane_aspect ограничивает экранное отношение ширины/высоты диапазоном 0.25–6; высота рабочего холста ограничена 64–4096 px. Для фасадов вне этого диапазона сохранение пропорций не гарантируется. Это ограничение вычислительного шаблона, не измерение размеров дома и не новый запрет на загрузку фото. Наклон раскладки minAreaRect в этой итерации не менялся. Проверка токена сравнивает UTF-8-байты и корректно отказывает на не-ASCII заголовке; для реального развёртывания используйте случайный ASCII-токен. Успешный прямой вызов helper с кириллическим секретом не доказывает переносимость такого заголовка через браузеры и прокси.

## Заявки, CRM и метрики

Постоянная таблица SQLite: `.facade-data/leads.sqlite3` (путь меняется FACADE_DATA_DIR). Таблица jobs содержит контакты, согласие, выбор, источник, статус и результат. leads содержит обращения по кнопкам. Никакая заявка не ведёт к оплате. Результат доступен по непредсказуемому UUID; его обладатель может видеть фото и нажимать кнопки, но GET результата не раскрывает контакты.

Чтобы менеджер мог получать таблицу и менять статус, установить секрет `FACADE_ADMIN_TOKEN` и обращаться с `Authorization: Bearer <секрет>`:

- GET `/api/facade/admin/leads.csv` — таблица, совместимая с Excel, с защитой от формул в ячейках.
- GET `/api/facade/admin/metrics` — показатели по источнику utm_source.
- PATCH `/api/facade/admin/leads/{id}`, JSON `{"status":"paid"}` — статусы contacted/measured/paid/closed.

Опционально FACADE_CRM_WEBHOOK (HTTPS) и FACADE_CRM_TOKEN: outbox автоматически отправляет заявки, Idempotency-Key = UUID заявки, до 20 попыток с часовым интервалом. Получатель должен дедуплицировать этот ключ. Без webhook заявки остаются в таблице; интерфейс сообщает о сохранении, а не о доставке менеджеру. Изменения оплаты в CRM не импортируются сами: интеграция должна вызвать защищённый PATCH. До запуска назначить ответственного за выгрузку таблицы или подключить webhook.

Обращения защищены UNIQUE(job, action) и транзакцией BEGIN IMMEDIATE. При миграции старых дублей остаётся исходный id, сохраняется наиболее продвинутый статус (включая paid), а объединённые записи и снимки outbox сохраняются в lead_merge_archive. Неотправленные дубли outbox убираются из очереди; отправленные остаются в истории. Архив удаляется вместе с истёкшим заданием, дополнительно ограничен 90 днями от объединения. Перед миграцией рабочей базы нужна резервная копия; резервные копии имеют отдельный контролируемый срок хранения. В одном процессе повторный параллельный запуск отправки outbox блокируется OUTBOX_LOCK. Гарантии дедупликации получателя и оповещения об исчерпании попыток всё ещё требуют отдельной настройки.

Телефон нормализуется до цифр с необязательным ведущим + (9–15 цифр), номера из одинаковых цифр отклоняются. Это базовая проверка формата, не подтверждение принадлежности номера. При экспорте телефоны, включая старые форматированные записи, нормализуются и выгружаются без апострофа; свободный текст остаётся защищён от формул. Дата выгрузки — ISO с Europe/Kyiv. Для сохранения + и начального нуля при импорте в Excel колонку следует задать как текст.

Фото, контакты, результаты, обращения и outbox удаляются через 90 дней (проверка каждый час и при старте). Просроченные ссылки сразу недоступны. Анонимные события сохраняются для агрегатной статистики, связи с UUID удаляются; резервные копии тоже должны соблюдать срок хранения. Фото не используются для обучения и не публикуются в каталог. Ответы API/результатов: noindex, nofollow, no-store, no-referrer. UUID не помещается в сторонние метрики.

## Проверка и запуск теста спроса

```sh
pip install pytest
python -m pytest facade/tests -q
```

Проверяются исходные цены, округление панелей, неизвестные значения, пороги, маски исключений, валидация фото, защита API и срок хранения. Автоматические тесты используют искусственную маску; они не заменяют проверку качества модели на реальных стенах. Собрать набор с согласиями владельцев, вручную разметить исключения, измерить ложные успешные наложения, подобрать пороги, затем запустить тест на 2–4 недели. Бизнес-метрики оплаты требуют обновления статусов менеджером/CRM. Среднее время обработки считается в секундах CPU-пайплайна и не обещается близким к нулю; ручная обработка не требуется.
